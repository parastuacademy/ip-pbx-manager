# ip-pbx-manager 📞

مدیریت تلفن آی‌پی (VoIP) با پنل فارسی — بر پایه Asterisk اپن‌سورس و آماده استقرار با داکر.
طراحی‌شده برای **سازمان‌های کوچک و متوسط** (آکادمی، کلینیک، مغازه، دفتر) — سبک، ساده و بدون پیچیدگی‌های مراکز تماس.

**هویت و رسالت — این پروژه فقط همین است:**

| هست | نیست |
|---|---|
| سانترال تک‌سرور و تک‌سازمان، ~۱۰ تماس همزمان، پنل فارسیِ بدون اصطلاح تلفنی | SaaS چندمستأجری، مرکز تماس (صف، نظرسنجی)، جایگزین هسته Asterisk |
| هر مشتری یک سرور مستقل؛ آینده: ریسلر چندسروری | رقابت با FreePBX در تعداد قابلیت |
| درآمد از نصب + پشتیبانی سالانه + سخت‌افزار | فروش لایسنس نرم‌افزار |

هر قابلیت تازه باید از فیلتر «مشکل کدام مشتری ایران را حل می‌کند؟» بگذرد؛ وگرنه ساخته نمی‌شود.

این پروژه یک **امتیج داکری چندنقشی** می‌سازد که بسته به متغیر محیطی `PBX_ROLE` یکی از سه نقش را اجرا می‌کند:

| نقش (`PBX_ROLE`) | چه چیزی اجرا می‌شود | چه پورت‌هایی لازم دارد |
|---|---|---|
| `asterisk` | هسته تماس Asterisk | `5060/udp` + `10000-10100/udp` |
| `panel` | پنل مدیریتی وب (Python/Flask) | `8080/tcp` |
| `all` | هر دو با هم (در یک کانتینر) | هر سه |

**معماری پیشنهادی: دو کانتینر از یک ایمیج** — پنل و هسته تماس جدا هستند تا ارتقای پنل، تماس‌های در جریان را قطع نکند. هر دو کانتینر یک ولوم مشترک `/data` دارند (کانفیگ‌ها، دیتابیس تماس‌ها، ضبط‌ها) و از طریق AMI روی شبکه داخلی داکر با هم حرف می‌زنند.

## ۱) راه‌اندازی سریع

### روش الف) پنل استقرار شما (بیلد از Dockerfile) — روش اصلی

پنل سرور شما پروژه را از گیت‌هاب بیلد می‌کند. کافی است:

1. در پنل استقرار، آدرس ریپو را بدهید تا از `Dockerfile` ایمیج ساخته شود.
2. **کانتینر اول — هسته تماس:** از ایمیج ساخته‌شده یک کانتینر بسازید:
   - متغیر محیطی: `PBX_ROLE=asterisk` و `AMI_PASSWORD=<یک رمز دلخواه قوی>`
   - پورت‌ها: `5060/udp` و `10000-10100/udp`
   - ولوم: یک ولوم/پوشه را روی `/data` سوار کنید
3. **کانتینر دوم — پنل:** دوباره از همان ایمیج یک کانتینر بسازید:
   - متغیرهای محیطی: `PBX_ROLE=panel` و `AMI_HOST=<نام یا آی‌پی کانتینر اول>` و `AMI_PASSWORD=<همان رمز بالا>`
   - پورت: `8080/tcp`
   - ولوم: **همان ولوم کانتینر اول** روی `/data`
4. پنل را باز کنید: `http://آی‌پی-سرور:8080`

### روش ب) Docker Compose (سرور شخصی)

```bash
git clone https://github.com/parastuacademy/ip-pbx-manager.git
cd ip-pbx-manager
AMI_PASSWORD="یک-رمز-قوی-انتخاب-کنید" docker compose up -d --build
```

### روش ج) سرور خالی لینوکس (یک دستور)

```bash
curl -fsSL https://raw.githubusercontent.com/parastuacademy/ip-pbx-manager/main/install.sh | sudo bash
```

## ۲) متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PBX_ROLE` | `all` | نقش کانتینر: `asterisk` / `panel` / `all` |
| `AMI_PASSWORD` | `ipbx-ami-change-me` | رمز اتصال پنل به Asterisk (حتماً عوض کنید؛ در هر دو کانتینر یکسان باشد) |
| `AMI_HOST` | `localhost` | آدرس کانتینر Asterisk از دید پنل (در حالت دوکانتینری: نام کانتینر اول) |
| `PANEL_PORT` | `8080` | پورت داخلی سرویس پنل |
| `TZ` | `Asia/Tehran` | منطقه زمانی (روی گزارش تماس‌ها اثر دارد) |

## ۳) پورت‌هایی که باید آزاد باشند

| پورت | پروتکل | کاربرد |
|---|---|---|
| 5060 | UDP | سیگنالینگ SIP (تلفن‌ها + ترانک پیشگامان) |
| 10000-10100 | UDP | صدای تماس‌ها (RTP) |
| 8080 | TCP | پنل مدیریت + پروویژنینگ تلفن‌های گرنداستریم |

> پورت AMI (5038) فقط داخل شبکه داخلی داکر استفاده می‌شود و بیرون منتشر **نمی‌شود**.

## ۴) راه‌اندازی اولیه داخل پنل

1. باز کردن `http://آی‌پی-سرور:8080` ← ساخت رمز مدیر (فقط بار اول)
2. ورود به پنل ← باز شدن **ویزارد راه‌اندازی**
3. در ویزارد: مشخصات ترانک پیشگامان (حالت Register یا IP-Peer، آدرس سرور، نام کاربری، رمز)، کدک‌ها و تعداد داخلی‌ها را وارد کنید
4. پنل به‌صورت خودکار کانفیگ‌های Asterisk را می‌نویسد و سرویس را بازخوانی (reload) می‌کند
5. برای هر تلفن گرنداستریم:
   - در پنل، شماره MAC گوشی را در داخلی مربوطه ثبت کنید
   - در وب‌رابط گوشی: مسیر **Maintenance → Upgrade/Provisioning** را باز کنید و Config Server Path را روی `http://آی‌پی-سرور:8080/provisioning/` بگذارید و گوشی را ری‌استارت کنید
   - گوشی به‌صورت خودکار داخلی، رمز و سرور را دریافت و ثبت می‌کند

## ۵) امکانات

**هسته تماس و داخلی‌ها**
- ویزارد راه‌اندازی سه‌مرحله‌ای (رمز مدیر، ترانک، داخلی‌ها)
- پشتیبانی ترانک در دو حالت: **Register** و **IP-Peer** (مطابق مدارک پیشگامان)
- ساخت/ویرایش/حذف داخلی‌ها + نمایش وضعیت آنلاین هر گوشی
- کلید **ضبط مکالمات برای هر داخلی** (پیش‌فرض خاموش)
- پروویژنینگ خودکار تلفن‌های گرنداستریم + **ثبت موبایل با QR** (Grandstream Wave / Zoiper)

**جریان تماس ورودی**
- **گروه زنگ (Ring Group)** — زنگ هم‌زمان روی چند داخلی با مقصد پیش‌فرض
- **منوی صوتی (IVR)** با پیام آپلودی فارسی و گزینه‌های قابل انتخاب
- **ساعات کاری هفتگی + تعطیلات با تقویم شمسی** — خارج از ساعت اداری، تماس به پیام صوتی می‌رود
- **وویس‌میل** برای هر داخلی + شنیدن/دانلود پیام‌ها از پنل + شماره‌گیری `*98` روی تلفن‌ها

**مدیریت و گزارش**
- داشبورد زنده: وضعیت ترانک، تلفن‌های آنلاین، تماس‌های فعال
- گزارش تماس‌ها (CDR) با **تاریخ شمسی**، فیلتر «فقط بی‌پاسخ» و **خروجی اکسل (CSV سازگار فارسی)**
- **نقش‌ها**: مدیر کامل + حساب «گزارش‌گیر» فقط-مشاهده برای مدیرعامل/منشی
- آرشیو ضبط‌ها با پخش و دانلود از پنل
- بازسازی کامل کانفیگ‌ها با یک کلیک

**اعلان‌ها و امنیت**
- **اعلان تلگرام / وبهوک (سازگار با بله و ایتا) / ایمیل** برای: تماس بی‌پاسخ ورودی، قطع/وصل شدن ترانک، حمله به ورود پنل
- **قفل‌گذاری هوشمند ورود** (۸ تلاش ناموفق = ۱۰ دقیقه مسدود) + گزارش امنیتی
- **پشتیبان‌گیری و بازیابی یک‌کلیکی** (تنظیمات + دیتابیس + ضبط‌ها)

**اتصال به نرم‌افزارهای دیگر (REST API)**
- **REST API با احراز هویت API Key** — کلیک‌به‌تماس (برقراری تماس از داخل CRM)، گزارش تماس‌ها، ضبط مکالمه، وضعیت داخلی‌ها و ترانک
- **وب‌هوک رخداد تماس‌ها** (`call.ended` / `call.answered` / `call.missed`) با امضای HMAC-SHA256 و تلاش مجدد خودکار — برای پاپ‌آپ پرونده مشتری و کارتابل تماس‌های از دست‌رفته
- مدیریت کلیدها و وب‌هوک‌ها از پنل: منوی **«اتصال‌ها (API)»** — محدودسازی IP، باطل‌کردن فوری، ارسال آزمایشی
- مستندات کامل فارسی با مثال‌های curl/PHP/Python: [`docs/API.md`](docs/API.md) + مشخصات OpenAPI: [`docs/openapi.yaml`](docs/openapi.yaml)

## ۶) REST API در یک نگاه

```bash
# ساخت کلید: پنل ← اتصال‌ها (API) ← ساخت کلید

# کلیک‌به‌تماس: اول گوشی کارمند ۱۰۱ زنگ می‌خورد، بعد به مشتری وصل می‌شود
curl -s http://آدرس-پنل:8080/api/v1/calls/click-to-call \
  -H "Authorization: Bearer pbx_...." -H "Content-Type: application/json" \
  -d '{"agent": "101", "destination": "09121234567"}'

# ۵۰ تماس بی‌پاسخ آخر
curl -s "http://آدرس-پنل:8080/api/v1/calls?disposition=NO%20ANSWER&limit=50" \
  -H "Authorization: Bearer pbx_...."
```

مستندات کامل: **[docs/API.md](docs/API.md)**

## ۷) امنیت

- رمز `AMI_PASSWORD` را از پیش‌فرض عوض کنید و پورت پنل را در فایروال فقط برای IP‌های مورد اعتماد باز بگذارید.
- پنل در اولین اجرا از شما می‌خواهد رمز مدیر بسازید؛ رمزهای داخلی‌ها هم به‌صورت تصادفی ساخته می‌شوند.
- فایل‌های حساس (کانفیگ‌ها، دیتابیس، ضبط‌ها) همگی داخل ولوم `/data` هستند؛ از همین پوشه بک‌آپ بگیرید.
- مسیر پروویژنینگ بدون احراز هویت است (الزام معماری گوشی‌های گرنداستریم)؛ تنها شامل مشخصات داخلی‌هاست و توصیه می‌شود در فایروال فقط برای شبکه محلی باز باشد.

## ۸) عیب‌یابی سریع

| مشکل | رایج‌ترین علت و راه‌حل |
|---|---|
| صدای تماس یک‌طرفه یا قطع صدا | سرور پشت NAT است؛ در صفحه تنظیمات پنل، «آی‌پی عمومی» را وارد و کانفیگ را بازسازی کنید |
| ترانک همیشه قرمز است | مشخصات پیشگامان (حالت Register یا Peer، نام کاربری، رمز) را با مدارک آنها مطابقت دهید |
| گوشی ثبت نمی‌شود | آدرس پروویژنینگ یا MAC ثبت‌شده در پنل را بررسی کنید؛ پورت 5060/udp از سمت شبکه گوشی باز باشد |
| پنل بالا می‌آید ولی همه‌چیز قرمز است | `AMI_HOST` و `AMI_PASSWORD` دو کانتینر باید یکی و درست باشد |

## ۹) ساختار پروژه

```
ip-pbx-manager/
├── Dockerfile              # ایمیج چندنقشی (Asterisk + پنل)
├── docker-compose.yml      # استقرار دوکانتینری استاندارد
├── install.sh              # نصب یک‌دستی روی سرور لینوکس خالی
├── entrypoint.sh           # انتخاب نقش کانتینر
├── asterisk/               # کانفیگ‌های پایه Asterisk (+ voicemail)
├── docs/                   # مستندات (API.md + openapi.yaml)
├── tests/                  # تست‌های API و وب‌هوک (unittest)
└── app/                    # پنل مدیریت (Python/Flask + قالب‌های فارسی)
    ├── ipbx/api.py         # REST API نسخه ۱ (/api/v1)
    ├── ipbx/webhooks.py    # موتور ارسال رخدادها با تلاش مجدد
    ├── ipbx/config_gen.py  # تولید کانفیگ‌ها (pjsip, dialplan, IVR, وویس‌میل)

    ├── ipbx/notifier.py    # اعلان‌ها (تلگرام/وبهوک/ایمیل)
    └── templates/          # صفحات فارسی RTL
```

## ۱۰) اصول ثابت و درس‌های تکرارنشدنی

اینها حاصل اشتباهات واقعی مسیر توسعه‌اند — هر تغییر با اینها سنجیده شود، تا وقت دوباره تلف نشود:

- **تا دیتای واقعی وجود ندارد، کد سازگاری/مهاجرت نوشته نمی‌شود** — کدِ «اگر ستون نبود اضافه کن» و «چیدمان قدیمی را هم تحمل کن» فقط برای دیتایی که هرگز شکل نگرفت نوشته شد و یک‌جا همه‌اش حذف شد. تمیز بنویسید؛ اگر روزی دیتای قدیمی آمد، همان‌جا تصمیم بگیرید.
- **هر منطق فقط یک‌جا** — منطق خواندن CDR سه بار تکرار شده بود و هر اصلاح باید سه بار اعمال می‌شد. تنها مرجع حالا `app/ipbx/cdr.py` است؛ ماژول دیگری خودش CDR را تفسیر نمی‌کند.
- **رفتار Asterisk را از سورس C همان نسخه تأیید کنید** — چیدمان ستون‌های CDR با حدس غلط بود و فقط با مطالعه `cdr_csv.c` درست درآمد.
- **هر تست وضعیت خودش را بسازد و پاک کند** — تستی که به فایل‌های به‌جامانده از اجرای قبل وابسته است، در اجرای دوم به‌دروغ قرمز می‌شود و وقت می‌گیرد.
- **اسناد فقط مطالب ارزشمند؛ نه قصه رویدادها** — سندی که «چه شد و چه شد» تعریف می‌کند حواس را از مطلب اصلی می‌پراکند. حذف مطالب کم‌ارزش از اسناد وظیفه است، نه سلیقه.
