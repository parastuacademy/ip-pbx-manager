# ip-pbx-manager 📞

مدیریت تلفن آی‌پی (VoIP) با پنل فارسی — بر پایه Asterisk اپن‌سورس و آماده استقرار با داکر.

این پروژه یک **امتیج داکری چندنقشی** می‌سازد که بسته به متغیر محیطی `PBX_ROLE` یکی از سه نقش را اجرا می‌کند:

| نقش (`PBX_ROLE`) | چه چیزی اجرا می‌شود | چه پورت‌هایی لازم دارد |
|---|---|---|
| `asterisk` | هسته تماس Asterisk | `5060/udp` + `10000-10100/udp` |
| `panel` | پنل مدیریتی وب (Python/Flask) | `8080/tcp` |
| `all` | هر دو با هم (در یک کانتینر) | هر سه |

**معماری پیشنهادی: دو کانتینر از یک ایمیج** — پنل و هسته تماس جدا هستند تا ارتقای پنل، تماس‌های در جریان را قطع نکند. هر دو کانتینر یک ولوم مشترک `/data` دارند (کانفیگ‌ها، دیتابیس تماس‌ها، ضبط‌ها) و از طریق AMI روی شبکه داخلی داکر با هم حرف می‌زنند.

## ۱) راه‌اندازی سریع

### روش الف) پنل استقرار شما (بیلد از Dockerfile) — روش اصلی

پنل سرور شما پروژه را از گیت‌هاب بیلد می‌کند. کافی است:

1. در پنل استقرار، آدرس ریپو را بدهید تا از `Dockerfile` ایمیج ساخته شود.
2. **کانتینر اول — هسته تماس:** از ایمیج ساخته‌شده یک کانتینر بسازید:
   - متغیر محیطی: `PBX_ROLE=asterisk` و `AMI_PASSWORD=<یک رمز دلخواه قوی>`
   - پورت‌ها: `5060/udp` و `10000-10100/udp`
   - ولوم: یک ولوم/پوشه را روی `/data` سوار کنید
3. **کانتینر دوم — پنل:** دوباره از همان ایمیج یک کانتینر بسازید:
   - متغیرهای محیطی: `PBX_ROLE=panel` و `AMI_HOST=<نام یا آی‌پی کانتینر اول>` و `AMI_PASSWORD=<همان رمز بالا>`
   - پورت: `8080/tcp`
   - ولوم: **همان ولوم کانتینر اول** روی `/data`
4. پنل را باز کنید: `http://آی‌پی-سرور:8080`

### روش ب) Docker Compose (سرور شخصی)

```bash
git clone https://github.com/parastuacademy/ip-pbx-manager.git
cd ip-pbx-manager
AMI_PASSWORD="یک-رمز-قوی-انتخاب-کنید" docker compose up -d --build
```

### روش ج) سرور خالی لینوکس (یک دستور)

```bash
curl -fsSL https://raw.githubusercontent.com/parastuacademy/ip-pbx-manager/main/install.sh | sudo bash
```

> این لینک‌ها مستقیماً به همین مخزن اشاره می‌کنند و بدون هیچ تغییری کار می‌کنند.

## ۲) متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PBX_ROLE` | `all` | نقش کانتینر: `asterisk` / `panel` / `all` |
| `AMI_PASSWORD` | `ipbx-ami-change-me` | رمز اتصال پنل به Asterisk (حتماً عوض کنید؛ در هر دو کانتینر یکسان باشد) |
| `AMI_HOST` | `localhost` | آدرس کانتینر Asterisk از دید پنل (در حالت دوکانتینری: نام کانتینر اول) |
| `PANEL_PORT` | `8080` | پورت داخلی سرویس پنل |
| `TZ` | `Asia/Tehran` | منطقه زمانی (روی گزارش تماس‌ها اثر دارد) |

## ۳) پورت‌هایی که باید آزاد باشند

| پورت | پروتکل | کاربرد |
|---|---|---|
| 5060 | UDP | سیگنالینگ SIP (تلفن‌ها + ترانک پیشگامان) |
| 10000-10100 | UDP | صدای تماس‌ها (RTP) |
| 8080 | TCP | پنل مدیریت + پروویژنینگ تلفن‌های گرنداستریم |

> پورت AMI (5038) فقط داخل شبکه داخلی داکر استفاده می‌شود و بیرون منتشر **نمی‌شود**.

---

## ۴) راه‌اندازی اولیه داخل پنل

1. باز کردن `http://آی‌پی-سرور:8080` ← ساخت رمز مدیر (فقط بار اول)
2. ورود به پنل ← باز شدن **ویزارد راه‌اندازی**
3. در ویزارد: مشخصات ترانک پیشگامان (حالت Register یا IP-Peer، آدرس سرور، نام کاربری، رمز)، کدک‌ها و تعداد داخلی‌ها را وارد کنید
4. پنل به‌صورت خودکار کانفیگ‌های Asterisk را می‌نویسد و سرویس را بازخوانی (reload) می‌کند
5. برای هر تلفن گرنداستریم:
   - در پنل، شماره MAC گوشی را در داخلی مربوطه ثبت کنید
   - در وب‌رابط گوشی: مسیر **Maintenance → Upgrade/Provisioning** را باز کنید و Config Server Path را روی `http://آی‌پی-سرور:8080/provisioning/` بگذارید و گوشی را ری‌استارت کنید
   - گوشی به‌صورت خودکار داخلی، رمز و سرور را دریافت و ثبت می‌کند

## ۵) امکانات نسخه ۱

- ویزارد راه‌اندازی سه‌مرحله‌ای (رمز مدیر، ترانک، داخلی‌ها)
- پشتیبانی ترانک در دو حالت: **Register** و **IP-Peer** (مطابق مدارک پیشگامان)
- ساخت/ویرایش/حذف داخلی‌ها + نمایش وضعیت آنلاین هر گوشی
- کلید **ضبط مکالمات برای هر داخلی** (پیش‌فرض خاموش)
- داشبورد زنده: وضعیت ترانک، تلفن‌های آنلاین، تماس‌های فعال
- گزارش تماس‌ها (CDR) با جست‌وجو و فیلتر تاریخ
- آرشیو ضبط‌ها با پخش و دانلود از پنل
- پروویژنینگ خودکار تلفن‌های گرنداستریم (سری‌های GXP16xx، GXP21xx، GRP2600 و سایر مدل‌های XML-سازگار)
- بازسازی کامل کانفیگ‌ها با یک کلیک از صفحه تنظیمات

## ۶) امنیت

- رمز `AMI_PASSWORD` را از پیش‌فرض عوض کنید و پورت پنل را در فایروال فقط برای IP‌های مورد اعتماد باز بگذارید.
- پنل در اولین اجرا از شما می‌خواهد رمز مدیر بسازید؛ رمزهای داخلی‌ها هم به‌صورت تصادفی ساخته می‌شوند.
- فایل‌های حساس (کانفیگ‌ها، دیتابیس، ضبط‌ها) همگی داخل ولوم `/data` هستند؛ از همین پوشه بک‌آپ بگیرید.
- مسیر پروویژنینگ بدون احراز هویت است (الزام معماری گوشی‌های گرنداستریم)؛ تنها شامل مشخصات داخلی‌هاست و توصیه می‌شود در فایروال فقط برای شبکه محلی باز باشد.

## ۷) عیب‌یابی سریع

| مشکل | رایج‌ترین علت و راه‌حل |
|---|---|
| صدای تماس یک‌طرفه یا قطع صدا | سرور پشت NAT است؛ در صفحه تنظیمات پنل، «آی‌پی عمومی» را وارد و کانفیگ را بازسازی کنید |
| ترانک همیشه قرمز است | مشخصات پیشگامان (حالت Register یا Peer، نام کاربری، رمز) را با مدارک آنها مطابقت دهید |
| گوشی ثبت نمی‌شود | آدرس پروویژنینگ یا MAC ثبت‌شده در پنل را بررسی کنید؛ پورت 5060/udp از سمت شبکه گوشی باز باشد |
| پنل بالا می‌آید ولی همه‌چیز قرمز است | `AMI_HOST` و `AMI_PASSWORD` دو کانتینر باید یکی و درست باشد |
